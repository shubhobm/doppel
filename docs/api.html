HTTP API for Doppel Chatbot Studio. All request and response bodies are JSON, except the file upload endpoint, which takes multipart/form-data.

Authentication

There are three ways to authenticate. Each endpoint lists the one it accepts.

Scheme How Used by
sessionCookie Call POST /api/auth/login. The response sets an HTTP-only cookie named midterm_session, valid for 7 days. Send it on later requests. In production the cookie is Secure, so it is only sent over HTTPS or to localhost. The web app, and admin scripts that log in
graderKey Header x-grader-key: <GRADER_API_KEY> POST /api/grader/query
adminKey Header x-admin-key: <ADMIN_API_KEY> /api/admin/key/*

If GRADER_API_KEY or ADMIN_API_KEY is not set on the server, the endpoints that use that key reject every request with 401.

Roles

Session endpoints check the logged-in user's role: STUDENT, GRADER or ADMIN. Endpoints under /api/bots, /api/chat and /api/documents only act on bots owned by the logged-in user, whatever their role. A bot owned by someone else returns 404.

Errors

Handled errors return a JSON body of the form {"error": "<message>"}. Some failures are not handled: a database error, a model error that the fallback doesn't catch, or a grader query for a missing or unsubmitted bot. These return 500 with Next.js's default response body, which is not JSON.

Identifiers

All IDs are CUID strings, for example cm5x8k2qv0001abcd1234efgh. In the database, a user's username is stored in a field named email. Responses use email or username for that same value, depending on the endpoint.

Auth

Log in, log out, change password.

Log in

Checks a username and password and sets the midterm_session cookie.

If the username is the built-in admin (STATIC_USERNAME in lib/limits.ts), the admin account is created on first login and accepts STATIC_PASSWORD until the admin changes the password. After that change, only the new password works.

Documents

Source files attached to a bot.

Upload source files to a bot

Stores each file, extracts its text, splits the text into chunks of about 1200 characters, and saves the chunks for retrieval. Files are processed in order. If one fails, processing stops and the request returns 500. Files already processed in that request are kept, and the failed file's document is marked FAILED.

Limits per bot: 100 files and 100 MB in total. Accepted types: PDF, DOCX, TXT and MD, checked by MIME type or file extension. On Vercel, each request must be under 4.5 MB, so the web app uploads one file per request.

Bulk-create students from CSV

Creates one STUDENT per data row of a CSV. The CSV must have a header row containing an Email ID column (matched case-insensitively). Other columns are ignored.

For each row, the username is the part of the email before @, and the starting password is the same as the username. Usernames that already exist are skipped. Blank rows are ignored.
